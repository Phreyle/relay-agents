---
name: ship
description: Pre-PR checks. Runs the slow checks the Stop gate skips, runs the reviewer agent, ticks a plan in progress, then commits, pushes and opens a PR after confirmation.
disable-model-invocation: true
argument-hint: [the task, in one line]
---
Ship the current work. Task: $ARGUMENTS (if empty, ask me for it in one line).

1. **Branch.** Run `git branch --show-current`. On `main` or `master`, propose a branch name `feat/<slug>` and `git switch -c` it. Never commit to or push `main`.
2. **Checks.** Read `.claude/relay.json`. Run the `cmd` of every `gates` entry, then of every `slow` entry, in order. Stop at the first failure, show the last 40 lines, and fix it or ask me. No `relay.json`: say so and suggest `/relay:setup-project`.
3. **Review.** Collect the change: `git diff <base>...HEAD` plus `git diff HEAD` (base is `origin/HEAD` if it exists, else `main`, else `master`), plus the contents of untracked files (`git ls-files --others --exclude-standard`), which a plain diff leaves out. Send the task and the change to the `relay:reviewer` agent. Show its findings. Fix blockers and majors, then re-run step 2.
4. **Plan.** Look in `docs/plans/` for plans with `Status: in progress`. None: skip this step. Use the one the task names (its slug or title, matched loosely); if the task names none, use the one whose phases the change matches. If the task fits several plans, or none fits, ask me in one line and tick nothing until I answer. Check every unticked box of that plan and tick those whose `Done when` holds now (run the command, or read the file or output). Run a plan's command only if it is safe to run now: nothing that deploys, sends messages or changes a database. If a check is unsafe to run, or is something only I can see, leave the box, say so, and carry on to step 5. Add one line at the end of its Log naming every phase you ticked and, in a few words, what the change did: `- <today>: Phase 2 done (overdue function)`. If you ticked nothing, leave the plan file alone and say why. Set `Status: done` only if every box is ticked and every `Done when` holds; if a box was already ticked and you cannot confirm it, leave that box and the Status as they are and tell me.
5. **Confirm before anything outward.** Show the files you will stage, by name (the plan too, if you changed it; never `git add -A`), the proposed commit message, and the PR title and body: what changed, the checks that passed, and the plan ticks and open phases. Ask before each of: commit (staging those files first), push, open the PR. No `origin` remote: say so and stop after the commit. Push with `git push -u origin <branch>` and open with `gh pr create`. Never merge, never force-push.
