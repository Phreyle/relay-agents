Set up relay in this repo. Show everything before writing anything, apart from ordinary build output left by the trial runs in step 2.

1. **Detect the stack.** Read `package.json` (scripts, lockfile), `pyproject.toml`, `requirements.txt`, `go.mod`, `Cargo.toml`, `Makefile`, and a few source and test files. Use the package manager the lockfile shows (npm when there is none). List the test, lint, typecheck, build and smoke commands you find. For each, read the script body, its `pre` and `post` hooks, and any `&&` chain. If a script just runs a file (for example `node build.mjs`), skim that file for deploy, publish and database calls.
2. **Try each candidate once** from the repo root (the folder with the manifest if there is no git repo), in its non-watch, non-interactive form (for example `vitest run`, or `jest --watchAll=false`). Use plain commands, not an env-var prefix like `CI=1`: it fails in Windows shells. Never run a command whose body, hooks or chain deploy, publish, release, touch a database, or rewrite source files (`--fix`, `--write`; a read-only `--check` is fine), even to try it. Stop any command still running after 5 minutes (raise your command timeout to match) and skip it as too slow. Keep a command only if it exits 0 today and needs no running server, database or network. Skip the rest and say why in one line each: failed today, needs a server, too slow, script or tool not found, or not run on purpose (say why).
   - `gates` run at every stop, so keep them fast: lint, typecheck and unit tests, about 60s together.
   - `slow` runs only in `/relay:ship`: the build, plus any passing check that would take the gates past about 60s. Anything that needs a running server goes in neither list.
3. **Draft `.claude/relay.json`** with the exact commands that passed, written expanded with 2-space indentation (the example is compacted) and with empty lists rather than missing keys. `timeoutSec` is a cap per command, not a target (120 unless a kept command needs more):
   `{"gates":[{"name":"test","cmd":"npm test"}],"slow":[{"name":"build","cmd":"npm run build"}],"timeoutSec":120}`
   If the file already exists, keep every existing entry unchanged and propose only new entries for commands it does not already run (`npm test` and `npm run test` are the same command); raise `timeoutSec` only if a new entry needs more. If an existing gate fails today, say so; do not remove it. If no gate qualifies, write `relay.json` only when a `slow` check passes (with `"gates": []`); otherwise write none. Either way, carry on with steps 4 to 6.
4. **AGENTS.md and CLAUDE.md.** The brief lives in `AGENTS.md`, which other coding agents read too. `CLAUDE.md` only imports it, so Claude loads it in every session. Below, "`CLAUDE.md`" means `./CLAUDE.md` or `.claude/CLAUDE.md` (if both exist, check each).
   - Neither exists: draft `AGENTS.md` under 35 lines in total: the project name and what it is, how to run each check you found (note any that need a server), conventions you actually observed in the code and tests, and a warning for any script that deploys or touches a database. No boilerplate. End with a `## Known traps` section holding this one line, as plain text rather than a bullet: `Add one line here each time something non-obvious costs you time: what happened and the fix.` Draft `./CLAUDE.md` containing only `@AGENTS.md` on its own line. Write it as plain text, never inside backticks: an import inside a code span is not expanded, so the brief would never load.
   - Only `AGENTS.md` exists: draft just that one-line `./CLAUDE.md` and leave `AGENTS.md` alone.
   - Only `CLAUDE.md` exists: leave it alone, say so, and do not create `AGENTS.md`.
   - Both exist: check whether `CLAUDE.md` imports `AGENTS.md`. An import is `@path` anywhere in a line, outside code fences and backticks, and it resolves relative to the file that holds it: `./CLAUDE.md` needs `@AGENTS.md` (or `@./AGENTS.md`) and `.claude/CLAUDE.md` needs `@../AGENTS.md`; the other form points nowhere. If it is wired, say so. If not, say Claude ignores `AGENTS.md` until `CLAUDE.md` imports it, and include the right line (added at the top, replacing a wrong import line) among the drafts in step 6, once for each `CLAUDE.md` that lacks it.
5. **Deny rules** for `permissions.deny` in `.claude/settings.json`: scripts and commands that deploy, publish, release, or touch a remote or production database (deny when unsure whether a database is remote). Find them in the `package.json` scripts, written for the repo's package manager (`Bash(npm run deploy*)`; for pnpm, yarn and bun also the form without `run`), and for these CLIs when the repo depends on them or has their config: wrangler deploy, vercel --prod, prisma migrate deploy, drizzle-kit push, supabase db push, and the equivalents in other stacks you detected (for example `make deploy`, `cargo publish`, `twine upload`). Also deny `npm publish` (or `pnpm`, `yarn`, `bun publish`) unless `package.json` has `"private": true`. Write script-name prefixes without a space before the star (`Bash(npm run deploy*)` also catches `deploy:prod`), and CLI subcommands with one (`Bash(npx wrangler deploy *)`, which also matches the bare command). On Windows, repeat each rule as `PowerShell(...)`: the PowerShell tool does not use `Bash(...)` rules. Create the file if it is missing, add `permissions.deny` if it is absent, and append to an existing list without duplicates; never overwrite or remove other keys. Deny rules are a guardrail, not a sandbox: `bash -c '...'` and `node deploy.mjs` can slip past them.
6. **Show** the drafts (`relay.json`, `AGENTS.md` with `CLAUDE.md`, deny rules) and the skip list, then ask me to confirm. Write the files only after I say yes. If I approve only part, write only that part, but treat `AGENTS.md` and its `CLAUDE.md` import as one item: write both or neither.
