relay-agents field guide

How to use it from inside Claude Code, written to be read cold after a long break. Relay makes Claude check its own work before it says it is done, helps you ship that work, and shows every Claude session on one board.

If you forget everything, do this

  1. Open Claude Code in your project folder. YOU REQUIRED
  2. First time in a project only: type /relay:setup-project and say yes to its plan. YOU REQUIRED once
  3. Work as usual. Ask for changes. Relay checks them every time Claude says it is done. ASK AI AUTO
  4. When you are happy, type /relay:ship and say yes to commit, push and the PR. YOU OPTIONAL
  5. Merge the PR in GitHub. GITHUB REQUIRED

Want to watch several projects at once? Type /relay:board. YOU OPTIONAL The board has a Guide button that shows this checklist in short.

The loop, and who does what

Only you can

  • Type slash commands: /relay:setup-project, /relay:ship, /relay:board, /reload-plugins, /plugin.
  • Say yes before Claude commits, pushes or opens a PR.
  • Click Merge in GitHub.

Claude can do itself

  • Edit code, run the checks, write tests, review a diff.
  • Commit, push and open a PR, each after your yes.
  • Run claude plugin ... commands to install or update relay (it has a working claude; your app terminal does not).
  • Inside /relay:ship it never merges, never force-pushes and never pushes main.

Step by step

A

Install relay (once per computer)

WhoYOU or ASK AI
Needed?REQUIRED once
Can the AI do it?Yes, after your yes. Or use the panel yourself.

On a new computer, first add the catalog: say "Add the relay-agents marketplace" and Claude runs claude plugin marketplace add Phreyle/relay-agents (the repo is private, so your GitHub login must work there). Then type /plugin install relay@relay-agents. It opens a panel where you pick a scope: for you in every project, shared with this repo, or just you in this repo. Or say "Install relay for all my projects" and Claude runs claude plugin install relay@relay-agents --scope user.

Right now relay is installed with the "just you in this repo" scope (--scope local) for relay-agents and Katiwala-App only. claude plugin list shows the version and scope. After any install or update, type /reload-plugins. Needs Node.js (the hooks and the board are Node scripts) and, for /relay:ship to open PRs, the gh command logged in to GitHub.

B

Set up a project (once per project)

WhoYOU then Claude works
Needed?REQUIRED once without it relay does nothing there
Can the AI do it?Yes. It does all the work and shows you the plan first.

Type /relay:setup-project. Claude finds your tests, lint and typecheck, keeps only the ones that pass today without a running server, and shows the plan. After your yes it writes:

  • .claude/relay.json: the checks. gates run every time Claude says done, so keep them fast. slow (builds, smoke tests) only run in /relay:ship.
  • A short CLAUDE.md, only if the project has none.
  • Deny rules in .claude/settings.json that block the deploy, publish and remote-database scripts it finds. A guardrail, not a lock: it blocks those script names, not every way to deploy.
C

Work normally. The gate runs by itself

WhoASK AI for changes, AUTO for checks
Needed?REQUIRED but automatic once step B is done
Can the AI do it?Claude edits. The gate needs nothing from either of you.

Say what you want, for example "Add a rent reminder for overdue tenants". When Claude says it is done and the project has uncommitted changes, relay runs your checks in order. A clean working tree skips them.

  • All pass: Claude may stop.
  • One fails: Claude gets the last 40 lines of that check and keeps working. After 3 blocked stops in a row in the same session, it lets Claude stop and warns that the check is still failing. A green run resets the count. Each session counts on its own.
D

Watch every session (optional)

WhoYOU then Claude starts it
Needed?OPTIONAL
Can the AI do it?Yes, after you type the command.

Type /relay:board. Claude starts a small local page at http://127.0.0.1:4317 and opens it. Each Claude session in any project with relay gets one card, updated within about a second. It runs as a background task of the session that started it. It stops when the PC restarts, and may stop when that session closes (not tested). If the dot says reconnecting, type /relay:board again: events are kept in a file, so the cards come back. Click Guide on the board for a short version of this page. See the board.

E

Ship it

WhoYOU then Claude works, you say yes
Needed?OPTIONAL
Can the AI do it?Yes. You can also just say "commit this and open a PR".

Type /relay:ship what you built. Claude makes sure you are on a branch (never main), runs the gates and the slow checks, has the read-only reviewer agent check the diff, fixes serious findings, then shows the status, the commit message and the PR text. It asks before the commit, before the push and before opening the PR.

Plain words skip the review and the slow checks. /relay:ship adds them.

F

Merge the PR

WhoGITHUB you
Needed?REQUIRED to land the change
Can the AI do it?Not through relay. /relay:ship never merges, by design.

The only step outside Claude Code. Open the PR link Claude gave you and click Merge.

G

Update relay itself (rare, only after you change relay)

WhoASK AI then YOU /reload-plugins
Needed?OPTIONAL
Can the AI do it?Everything except /reload-plugins.
  • Ask Claude to change relay in the relay-agents project. It works on a branch and bumps version in plugins/relay/.claude-plugin/plugin.json. Without that bump, installs keep the old copy.
  • Merge the PR in GitHub.
  • Say "Update relay in all my projects". Claude runs claude plugin marketplace update relay-agents, then claude plugin update relay@relay-agents --scope local from each project that has relay installed, asking before each. Use the scope you installed with.
  • Type /reload-plugins in every open session.
  • Restart the board if it is running: ask Claude to stop it, then type /relay:board. A running board keeps the old code until then.

Ask Claude to run claude plugin marketplace list first. On this computer the relay-agents marketplace has flipped between GitHub and the local folder. To try an unmerged change first, start Claude from a terminal with claude --plugin-dir ./plugins/relay; it replaces the installed copy for that one session.

Blocked 1/3A check failed and Claude is fixing itNothing. AUTO
Still failing3 blocked stops in a row, so relay let Claude stopRead the failing check, then fix it or ask Claude to
Ready to shipAll checks passedKeep going, or type /relay:ship
Working Checking gatesA prompt was sent, or the checks are runningNothing
Turn finishedThe turn ended and no checks ran: no relay.json there, or nothing changedNothing. Run /relay:setup-project if you expected checks

Cards for sessions quiet for 12 hours disappear (24 hours for needs you and blocked). A card appears only after a real session start or prompt, so a gate tested by hand never gets one. Several sessions in one project show a short tag.

When something looks wrong

My terminal says "claude is not recognized"

The terminals inside the Claude app on this computer do not have the npm folder on their PATH. Ask Claude to run the command: its own shell finds claude. Or, in PowerShell: & "$env:APPDATA\npm\claude.cmd" plugin details relay. A restart of the Claude app may fix it for good (not confirmed).

The board says "reconnecting"

The board server is not running: its session closed or the PC restarted. In any Claude session type /relay:board. Events are kept in a file, so the cards come back.

The board is empty, or a project never shows up
  • Relay is not enabled there: install it (step A) and run /relay:setup-project (step B).
  • You updated relay but did not type /reload-plugins in that session.
  • A session already running when relay loaded appears after its next prompt.
I merged a relay change but nothing changed

Check that version was bumped, then update (step G) and type /reload-plugins. claude plugin details relay shows which version is installed.

A card says "Still failing"

Relay blocked 3 stops in a row and gave up. Read the failing check, fix it, and the next green run resets the count.

The gate is too slow or too strict

Edit .claude/relay.json: keep gates fast and move builds into slow. To switch the checks off in one project, rename or delete that file. The board still lists that project's sessions.

What is proven and what is not

Seen working in real sessions: the gate blocking a failing check (before the board existed), passing and skipped gate events reaching the board, cards for several projects at once, SessionEnd events recorded when sessions closed, the board starting from /relay:board, and the review step of /relay:ship.

Not seen yet: a real "needs you" card from a live permission prompt, a "blocked" card from a real failing check (tested with made-up events only), the delay the hooks add per event, old cards expiring on a live board (tested only in code), and what happens to the board when the session that started it closes.

Known limits: "needs you" stays until the next event, because nothing fires when you answer a prompt. "Ready to ship" only means the checks passed, not that you committed.
